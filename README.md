# fluffy-octo-potato: cs32 final project

## an ingredient-based recipe recommender ##

My final project choice is a recipe recommendation tool that suggests recipes based on ingredients the user already has at home. The goal is to help users decide what they can cook without needing to search manually or buy many additional ingredients.

The program takes user input, compares it against a dataset of recipes stored in a CSV file, and returns the top matches ranked by how well the ingredients align.

## Features ##

- Accepts user input for available ingredients
- Loads recipe data from a CSV file
- Compares user ingredients to recipe ingredients
- Calculates a **percentage match score** for each recipe
- Filters out weak matches (below 50%)
- Displays the **top 5 best recipe matches**
- Shows **missing ingredients** for each recipe
- Handles capitalization differences in input

---

## File Structure ##

- recipe_recommender.py # Main program (user interaction + output)
- recipe_lib.py # Helper functions (data loading, matching, scoring)
- recipes.csv # Recipe dataset

---

## How It Works ##

1. The user enters ingredients one at a time.
2. The program loads recipes from `recipes.csv`.
3. For each recipe:
   - It counts how many ingredients match the user's input
   - It calculates a score based on the percentage of matched ingredients
4. Recipes with at least a 50% match are kept.
5. The remaining recipes are sorted by score from highest to lowest.
6. The top 5 recipes are displayed, along with missing ingredients.

___

## How to Run ##

1. Make sure all files are in the same folder:
   - `recipe_recommender.py`
   - `recipe_lib.py`
   - `recipes.csv`

2. Run the program:
   python3 recipe_rec.py

3. Enter ingredients when prompted, and type `done` when finished.

## Design Decisions ##

One key design decision was switching from a simple match count to a **percentage-based scoring system**. This ensures that recipes are ranked more accurately. For example, a recipe with 3 out of 3 matching ingredients is ranked higher than one with 3 out of 5, even though both have the same number of matches.

Another design decision was separating helper functions into `recipe_lib.py`. This makes the main program cleaner, easier to read, and easier to maintain.

---

## Challenges ##

One challenge was handling inconsistent user input, such as capitalization differences (e.g., "Eggs" vs "eggs"). This was resolved by converting all user input to lowercase before processing.

Another challenge was determining how to filter out weak recommendations. Initially, the program returned too many low-quality matches. This was improved by requiring at least a 50% ingredient match.
